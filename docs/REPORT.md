# Combat Sandbox v0.1 — отчёт

## Реализованные механики
- **Бой**: 100 HP, 3 независимых взвешенных барабана, 6 символов, тройки заменяют эффекты,
  суммирование смешанных эффектов, лимит лечения, щит на один удар со сгоранием перед своим ходом,
  доп. ходы (1 за смешанный спин, 2 за тройку, ≤ 2 подряд), одновременный урон/самоурон, двойной KO = ничья,
  лимит 40 вращений с победой по HP. Все числа — из `docs/balance.json`, файл валидируется при загрузке.
- **Режимы**: бой с ботом (тот же движок и правила, бот «жмёт кнопку» после паузы), локальный бой вдвоём,
  экран результата со статистикой, реванш (первым ходит другой), журнал боя, лист правил.
- **Детерминизм**: состояние RNG живёт в `BattleState`; один seed — один и тот же бой. Это задел под
  серверное авторитетное состояние и реплеи.
- **Визуальная обратная связь** (программно, без спрайтшитов): покачивание в idle; рывок при ударе;
  усиленный рывок + оранжевое свечение, белая вспышка и тряска при крите; отскок с красной маской
  по силуэту при попадании; пузырь щита и вспышка блока; зелёное свечение и «плюсики» при лечении;
  кувырок при самоуроне; падение со звёздами при KO; прыжки победителя; вращение барабанов с
  размытием и пружинной остановкой по очереди; золотая вспышка автомата при тройке; комиксные надписи
  («ПРОПУСТИЛ!», «КРИТ!», «СУПЕРУДАР!», «БЛОК!», «ХИЛ!», «НОКАУТ!» и др.); всплывающие числа;
  HP-бары со «шлейфом» урона и пульсацией на низком HP; вибрация на мобильных.
- **Мобильная адаптация**: портретный макет на 100dvh, safe-area, container queries для арены,
  проверено на 390×844, 360×640 и десктопе (рамка «телефона»); `prefers-reduced-motion` ускоряет
  таймлайн и отключает фоновые анимации.
- **Debug**: seed, номер хода, фаза, счётчик отклонённых кликов, состояние серии доп. ходов и щитов;
  принудительная комбинация (3 селекта + 10 пресетов, включая все тройки); установка HP; новый бой с seed;
  скорость ×0.5–×4; пауза бота.
- **Симуляция**: N боёв (по умолчанию 10 000) в Web Worker, отчёт: win rate P1/P2/ничьи, победы начавшего,
  причины окончания, длительность в ходах (среднее, медиана, p10–p90, мин–макс, гистограмма),
  частоты символов (ожидаемая vs фактическая), частоты троек и эффектов, поглощение щитами, лечение
  впустую, доп. ходы, экспорт JSON. То же доступно из CLI: `npm run simulate`.

### Ошибки, найденные и исправленные в ходе тестирования
1. Нечитаемые заголовки: «грязный» шрифт с обводкой превращался в кляксы → Rubik Black Italic + контур тенью.
2. Нокаутированный боец улетал за край экрана, затем проваливался под пол → поворот вокруг центра спрайта со смещением к центру ринга.
3. Во время анимации своего спина HUD, счётчик и кнопка уже показывали ход соперника → отображается ход, который анимируется.
4. «НОКАУТ!» дублировался под экраном результата; панель результата просвечивала → скрытие надписи, непрозрачный низ.
5. Всплывающие числа и пузырь щита были привязаны к рамке, а не к спрайту → позиционирование от реальной высоты спрайта.
6. Красная подсветка попадания через sepia делала белого Буля рыжим → маска по силуэту спрайта.
7. Тряска экрана через перемонтирование арены сбрасывала анимации бойцов → Web Animations API.
8. Ошибка в собственном тесте реванша (бой закончился раньше ожидаемого) — исправлен тест, не движок.

## Баланс по симуляции (10 000 боёв, seed 1, чередование первого хода)
- Победы P1 / P2 / ничьи: **49,9% / 50,1% / 0%**; все бои заканчиваются нокаутом (лимит 40 — ≈ 1 бой на 10 000).
- Длительность: среднее **11,7** вращения (≈ 5,9 на бойца), медиана 11, p10–p90 7–18, мин 3, макс 39.
- **Победы начавшего: 60,9%** — заметное преимущество первого хода.
- Тройки: 7,6% спинов (удар 6,5%, крит 0,4%, блок/лечение по 0,3%, промах 0,1%, молния ≈ 0,01%).
- Урон есть в 91% спинов, в среднем 21,7 за спин; щиты поглощают ≈ 16% урона; ≈ 15% лечения уходит в лимит.
- HP победителя в среднем 38,8; камбэков (победитель отставал после 6-го хода) — 21,7%.

## Известные проблемы и ограничения
- **Преимущество первого хода ~61%.** Для дуэлей это много; варианты: второму игроку стартовый щит 10,
  меньше урона за первый спин или первый ход по жребию (реванш уже чередует, но одиночный бой — нет).
- Арт временный: автоматическая маска по тёмному фону, низкое исходное разрешение (вырезки ~220×280,
  растянуты до 512); местами видны тёмные ореолы. Нет поз удара/KO — всё через трансформации.
- Тройка молний почти не выпадает (1 на ~8 000 спинов) — в живой игре практически невидима.
- Трактовки правил (см. IMPLEMENTATION_PLAN) нужно подтвердить у геймдизайна — особенно сгорание
  щита перед *доп.* ходом: оно делает комбинацию «щит + молния» бесполезной для защиты.
- Звука нет. Шрифт Rubik грузится всеми подмножествами (браузер берёт только нужные по unicode-range).
- 2 предупреждения линтера в `Reels.tsx` оставлены намеренно (лента барабана пересоздаётся на каждый спин).
- Бот не принимает решений: в правилах v0.1 их нет — только вращение.
